更新时间：2026-10-30

## 一、当前结构

```
https://stillfloating.top/            ← 3D 星球入口页（WordPress 插件渲染）
   ├─ BLOG / 博客  → https://stillfloating.top/?sf_blog=1   （博客首页，?from=portal&theme=… 衔接日夜过渡）
   └─ QUIZ / 刷题  → https://quiz.stillfloating.top/        （刷题站，?from=portal&theme=…）

https://quiz.stillfloating.top/       ← 刷题站（Node 服务 127.0.0.1:3107，nginx 反代）
```

入口页与博客共用同一个 WordPress 站点：根路径用 3D 开屏模板，带 `?sf_blog=1`
或 `?from=portal` 时走正常博客模板。刷题站是独立站点，未做任何改动。

## 七、进入博客时的壁纸修复（transition.php）

问题现象：从入口页进入博客的瞬间，壁纸发白/发灰，并且会错位一下再回正。

两个原因（都在 `still-floating-portal/transition.php` 的到站脚本里）：

1. 脚本给 `body` 加了 `transform: translateY(22px)` 和 `opacity: .65`。
   - Argon 的整页壁纸是 `#content:before` 的 `position: fixed; z-index: -2` 伪元素。
     `body` 一旦有 `transform`，这个固定定位元素就改以 body 为包含块，壁纸被重新缩放/位移，
     过渡结束时突然弹回——就是“错位一下”。
   - `body` 的 0.65 不透明度会和壁纸自身的 0.7 相乘（实测壁纸亮度掉到 63%），整页发灰发白。
2. 揭幕遮罩等 `window.load` + `document.fonts.ready` 才开始淡出，重页面下纯渐变会盖住壁纸
   1.5–2.5 秒，加上入口页自己的 1.15s 擦除，进门后很久看不到壁纸。

修复：

- 不再动 `body` 的 transform/opacity；改为只让页面内容上浮，壁纸完全不受影响：
  `#banner` 与 `#content > *` 做 `translateY(18px) → 0`（1050ms）。
- 揭幕改为 `DOMContentLoaded` 时立刻开始，淡出 620ms → 350ms，不再等图片和字体。
- 顺带发现（未改动）：`stillfloating-optimizations/assets/design.css` 第 5 行有
  `html.darkmode body #content:after{opacity:.12!important}`，夜间模式整页壁纸只有 12% 不透明度，
  若要夜间壁纸更明显，改这个数值即可。

## 十、刷题站（quiz.stillfloating.top）壁纸与图标

### 10.1 壁纸首帧

现象：进入刷题站后先看到一块纯色背景，约 1–2 秒后壁纸才“跳”出来。

原因：整页壁纸是 `.wallpaper-day / .wallpaper-night` 两个 CSS 图层，
`<img>` 不在 HTML 里，浏览器要等 React 挂载、样式表解析后才开始下载
（60–110KB webp），慢网下这段时间只有 `body` 的纯色底。

修复（`theme-init.js`，仍是同源外部脚本，符合 CSP）：

1. 按当前主题 + 视口（≤767px 用移动版图）选壁纸，`<link rel=preload>` 提前下载；
2. 在应用挂载前把同一张图直接铺到 `html` / `body` 背景上（`html.quiz-wallpaper-boot`）；
3. 首帧期间用 `display:none` 屏蔽另一个主题的图层，避免两张大图抢带宽；
4. 等「图片 decode 完成 + #root 已挂载」后撤掉类名，交还给应用自己的壁纸层；
   若应用中途改写了 `data-theme`（说明它已按自己的状态渲染）则立即撤掉。

实测：壁纸可见时间从约 2.6s 提前到约 0.6s（本地 60KB 图 1.2s 下载的情况下）。

### 10.3 nginx 缓存（重要）

`/www/server/nginx/conf/proxy.conf` 里的 `proxy_cache cache_one;` 会作用于所有
`proxy_pass` 站点，刷题站的 HTML 和 `/assets/*` 因此被 nginx 缓存最长 1 天，
发布新 bundle 后浏览器仍会拿到旧副本（裸文件名不带查询串）。

已在 `quiz.stillfloating.top.conf` 的 443 `location /` 内加 `proxy_cache off;`
（备份 `/root/site-backup/quiz-vhost-*.conf`），并给 `index.html` 里的主 bundle
加了 `?v=20261030` 作双保险。以后刷题站更新只需要覆盖文件，不用再等缓存过期。

回滚：`/root/site-backup/quiz-20261030-214916/`（index.html、theme-init.js、两个 bundle 原件）。

## 十一、刷题站前端统一（2026-10-30 第二轮）

### 11.1 现状问题（审查结论）

逐页看过首页 / 使用说明 / 我的反馈 / 好友 / 排行榜 / 账户 / 题库导入 / 代码题库 / 答题页 / 登录弹窗 / 反馈弹窗 / 顶栏下拉 / 手机抽屉后，主要问题：

1. **半透明卡片压在插画壁纸上**：卡片 78%–90% 不透明度 + 背景模糊，插画从卡片里透出来，正文对比度低、边缘糊在画里（题库导入、我的反馈、使用说明最明显）。
2. 页面头部层级弱：标题和正文挤在一起，返回按钮、面包屑、标题三者的字号和颜色没有层次。
3. 组件规格不统一：标签页一个圆角、输入框一个圆角、按钮一个高度；排行榜的空状态是虚线大框，反馈页的是实线卡片。
4. 手机端页面标题重复出现两次（顶栏一次 + 页面内一次）。
5. 「使用说明」页末尾的「关于记录」段落没有实际用处，且卡片太宽（一行约 100 字）。
6. 代码题库 / 账户设置两页没有壁纸，背景很空，显得像半成品。

### 11.2 处理方式

源码不在服务器上，所以新增一层后置样式表统一修正，不改构建产物里的组件：

- `/assets/ui-polish.css`：设计覆盖层（卡片实底、圆角/描边/阴影、标题层级、按钮/输入框/标签、表格、空状态、弹窗、夜间模式、移动端、内容页壁纸压暗到 42%）。
- `/assets/ui-polish.js`：同源脚本，渲染后删掉「关于记录」段落（React 重渲染时用 MutationObserver 兜底），并给内容页加 `ui-content-page` 标记。
- `index.html` 在应用样式表之后引入这两个文件（带 `?v=` 版本号，见 `deploy-ui.sh`）。

关键取舍：

- **不再用模糊+低透明显质感**：内容卡片 100% 实底，靠 1px 描边 + 双层阴影做层次；壁纸只作为页面底纹（浅色 42% / 夜间 30%），保证任何壁纸下正文都可读。
- **首页大面板是唯一例外**：它压在整页插画上，保留 94% + 模糊，视觉上仍是“浮在画上”的卡片。
- 统一规格：卡片圆角 16px、按钮 10px/38px 高、输入框 10px/40px 高、页面宽度 880px（使用说明 780px）、内容区 padding 30/24。
- 排行榜的分段控件改成胶囊滑块（选中实心主色），说明列表改成主色小圆点。
- 手机端：隐藏顶栏重复标题，页面标题 24px，分段控件整行铺满。
- 代码题库 / 账户设置这类没有壁纸的页面，用两团极淡的主色/暖色径向光晕补底。

## 十三、入口衔接 + 歌词文案（2026-10-31）

### 13.1 入口 → 刷题站的到站过渡

问题：从 3D 开屏点「QUIZ / 刷题」后，入口页有 1.15s 擦除动画，落到刷题站却是硬切，中间没有衔接。

处理（`theme-init.js`，仍是同源外部脚本，符合 CSP）：

- 仅在 `?from=portal` 时生效，直接访问刷题站不播；

- 落地后用 `history.replaceState` 清掉 `from/theme` 参数，刷新不会重复播过渡。

### 13.2 文案换成歌词

用户反馈首页的鼓励语/运势签语「太像 AI」。歌词来源是博客里自己维护的那套：

替换范围（`patch-copy.py`，对主 bundle 和共享 chunk 各打一遍）：

- 时钟下方的轮换语 `Pi`：日间 6 条 / 夜间 6 条 → 歌词（例：`Getting strong today — Spiritualized`、

## 十四、侧栏跳转 bug 修复（2026-10-31）

现象：点侧栏「题库 / 错题收藏 / 错题分析 / AI 学习总结」没反应（不滚动），
而且滚动首页时高亮会莫名跳到「AI 学习总结」。

根因（都是第十二节首页折叠引入的）：

1. 折叠用的是 `display:none`，被隐藏板块的 `getBoundingClientRect().top` 全为 0；
   应用自己的滚动高亮（`Xn`）是按 `section.top <= min(180, 30vh)` 逐项比较、保留最后一个命中的，
   0 <= 180 让四个隐藏板块全部命中，于是高亮永远落在最后一个（AI 学习总结）。
2. 点击锚点时目标不可见，应用算不出滚动位置，等于点了没反应。

修复（`ui-polish.css` + `ui-polish.js`）：

- 折叠改为「零高度 + `visibility:hidden` + `pointer-events:none`」，
  板块仍占位（rect.top 是真实流位置），滚动高亮恢复正常；
- 点击指向折叠板块的侧栏项时：先展开（`homeExpandedByUser=true`，重渲染后也不会再折回），
  再把这次点击重新派发一次，让应用在展开后的布局里完成滚动与高亮；
- 带 `#ai-summary` 直接打开时也会自动展开并定位。

验证（1440×800）：

- 折叠状态滚动：400px → 高亮「首页」，1200px → 「学习概览」（不再误判 AI 总结）；
- 依次点击 学习概览 / 今日练习 / 题库 / 错题收藏 / 错题分析 / AI 学习总结，
  六个锚点都滚动到对应板块（`top≈72`，避开 56px 顶栏）且高亮正确；
- 直接访问 `/#ai-summary`：页面展开、定位到该板块、高亮正确；
- 手机 390×844：默认折叠 + 展开按钮正常，无报错。
